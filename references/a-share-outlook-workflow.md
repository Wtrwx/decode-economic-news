# A股个股与ETF展望流程

当用户问“如何看某代码未来走势”时读取本文件。目标不是固定选择“先新闻、先外盘或先动量”，而是先通过事件时钟决定分支，再把因果判断与交易时机分开。

## 1. 不可跳过的起点

先确认四件事；任一项不清楚时不得进入预测：

1. 代码对应的证券、交易所与资产类型。
2. 观察时间、当时已公开的信息和预测周期。
3. 标的真正暴露的指数、行业、成份股或利润变量。
4. 比较基准。ETF至少同时检查跟踪指数和A股宽基；不要把跟踪指数当作超额收益基准。

运行：

```bash
python3 scripts/build_a_share_outlook_plan.py --code 588080 \
  --horizon 20d --session after_close --event-state unknown \
  --output work/588080-outlook-plan.json
```

`event-state=unknown` 表示先做事件时钟扫描，再选择分支；它不等于“没有新闻”。扫描覆盖24小时、7日和30日，优先调用NewsNook API，并要求每个所选源留下成功、无匹配或失败结果；只有API门禁触发时才对明确缺口使用浏览器fallback。

## 2. 默认优先级

| 优先级 | 模块 | 作用 | 能否单独定方向 |
|---|---|---|---|
| P0 | 标的身份、实时暴露、观察日与周期 | 防止分析错对象 | 否；这是门禁 |
| P1 | 事件时钟 | 决定新闻是否应升到第一因果位 | 否 |
| P2 | 本地预期状态 | 用相对动量、广度、量能和波动判断市场已定价多少 | 否 |
| P2 | 多周期技术择时 | 完成周线定方向、日线读突破/回踩，给出ATR风险尺度 | 否；必须再过资产级回测门禁 |
| P2 | 新闻原稿与披露 | 找到触发、约束和可量化传导变量 | 否 |
| P3 | 美股/韩股同变量映射 | 做跨市场自然对照并检验共同驱动 | 否 |
| P3 | A股接受/拒绝、资金与期权 | 判断本地流动性、拥挤和风险定价 | 否 |
| P4 | 因果综合、回测与情景 | 形成条件结论和失效条件 | 可以，且必须经过门禁 |

P2的内部顺序不是固定的，由事件时钟决定。动量提前出现，是为了读取预期和选择时机，不是为了替代新闻机制。

## 3. 事件时钟分支

### A. 无新近重大事件

顺序：`身份/暴露 -> 本地预期状态 -> 新闻原稿 -> 外盘同变量 -> 本地接受/资金 -> 回测与情景`。

理由：先知道价格、相对强弱和广度处于什么状态，才能判断后续新闻是否已被定价、是否只是一种事后解释。

只有当NewsNook-first新闻覆盖门禁通过且没有找到可改变现金流或折现率的新事件时，才能标记“无重大事件”。若API失败、无匹配或关键原文无法核验，必须完成定向浏览器fallback；API本身已经充分时不要求浏览器扫描。

### B. 已确认的新近重大事件

顺序：`身份/暴露 -> 事件原稿 -> 事件前本地定价 -> 外盘同变量反应 -> A股接受/拒绝 -> 动量与资金确认 -> 情景`。

重大事件需同时满足：原始来源可打开、影响变量明确、可能在所选周期内改变现金流或折现率。传闻、转载数量或标题情绪不满足该门槛。

### C. 传闻、政策吹风或来源未核验

顺序：`身份/暴露 -> 本地预期状态 -> 追溯原始来源 -> 观察成交与反转 -> 外盘只作旁证 -> 暂缓方向结论`。

不要让热搜或重复转载把来源不明的消息升级成基本面事实。

## 4. 不同会话和周期的顺序

### A股开盘前

`身份/暴露 -> 隔夜官方消息 -> 前一美股收盘与严格更早的韩股收盘 -> A股上一交易日状态 -> 开盘后接受/拒绝`。

不能用当天韩股收盘预测当天A股开盘。开盘跳空本身也不是确认；至少观察相对基准、量能和后续承接。

### 盘中

先冻结当时可见信息，再比较标的、跟踪指数和宽基的同步反应。未取得带时间戳的外盘盘中数据时，不把日线收盘数据伪装成实时先导。

### 收盘后，5日/20日展望

在没有重大新事件时先算本地趋势、相对强弱、广度和量能，再读新闻原稿并做外盘映射。5日更重视5/20日动量和开收盘接受；20日更重视20/60日相对强弱、成份股广度、盈利催化与估值约束。

若用户还问买卖点、入场条件或命名标的推荐，接着读取 `technical-timing-workflow.md`：用完成周线做方向门禁，日线 prior 20/55 日通道做触发，ATR/10日通道做风险参考。信号日收盘后才冻结，最早下一交易日执行。

### 60日以上或6至12个月

顺序改为：`暴露 -> 盈利/产业/政策原稿 -> 估值与现金流 -> 外盘结构变量 -> 本地持仓与流动性 -> 动量仅用于择时`。短周期技术分数不得外推成长周期基本面。

## 5. ETF附加门禁

1. 读取当前指数成份和基金最近披露持仓，记录两个日期；两者不可混写为“当前”。
2. 检查前十大权重、最大成份股、行业集中度和指数调样。
3. 检查ETF份额/净申赎、成交、折溢价、跟踪偏离；有期权时再看IV、偏度和持仓量。
4. 外盘映射必须按已核验的行业暴露动态选择。缺少权重时分别呈现，不计算看似精确的混合分数。
5. 技术分析以ETF价格为交易对象，因果分析以成份股利润变量为对象。

## 6. 588080示例

588080跟踪上证科创板50成份指数。正确起点不是“科创板=半导体”，而是先取得最新50只成份股和行业权重，再回答它在观察日主要押注什么。

默认无重大事件的20日流程：

1. 比较588080对沪深300的20/60日相对强弱、均线、量能、波动和回撤；加入成份股广度。
2. 查看最新指数调整、基金报告和前十大成份股公告，找出真正改变盈利或折现率的原稿。
3. 若半导体、科技、创新药或新能源任一暴露达到10%，分别运行对应美股/韩股映射。只有同日行业权重完整时才汇总。
4. 检验外盘变化是否来自共同变量，而非单纯全球风险偏好；再看588080相对A股宽基是接受还是拒绝。
5. 加入ETF申赎、折溢价和科创板50ETF期权的IV/偏度/OI，判断拥挤和尾部风险。
6. 最后给出基准、上行和下行情景，各自写触发、确认、失效与复核日。

若需要把候选标的升级为 `条件买入`，还必须运行：

`work/588080-history.json` 应包含足够长的历史（目标约 2,500 个以上交易日），并在看结果前冻结评估起点；360 根左右的数据只够计算当前状态，不足以支持资产级门禁。

```bash
python3 scripts/compute_trade_timing.py work/588080-history.json \
  --asset-code 588080 --benchmark-code 000300 \
  --output work/588080-trade-timing.json
python3 scripts/backtest_trade_timing.py work/588080-history.json \
  --asset-code 588080 --benchmark-code 000300 --horizon 20 --start 2022-01-01 \
  --cost-bps 20 --slippage-bps 10 \
  --output work/588080-timing-backtest.json
```

`triggered|retest` 之外的状态、未完成周线、同日成交假设或 timing backtest=`abstain` 都只能观察。

无论分数高低，先运行 `backtest_sector_signal.py`。若结果为 `abstain`，只报告证据、预期差和情景，不给方向性交易判断。

如果刚发生可核验的重大事件，第2步升到第1分析位，但仍要回看事件前5日价格，以防把已定价利好重复计算。

## 7. 最小交付格式

```text
标的 / 暴露日期 / 观察日 / 周期：
事件时钟与采用分支：
本地预期状态（绝对与相对）：
新闻原稿 -> 共享变量 -> 利润/折现率传导：
美股/韩股观察日、映射强度与共同因子剔除：
A股接受/拒绝与本地修正：
资金、ETF和期权定位：
多周期择时状态、下一交易日执行时钟与资产级回测门禁：
基准 / 上行 / 下行情景：
触发、失效、复核日与数据缺口：
```
